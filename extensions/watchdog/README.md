Reports failed runs to their subagent owner or @ultimate, and reminds @ultimate about open branches idle for more than 30 minutes (two hours while the branch waits on another conversation's reply; at @ultimate's turn end or after 10 minutes while it waits on @ultimate's answer).

Provider errors classified as temporary by Pi, and Claude Code relay responses that ended incomplete with status 200 or unknown, get one continuation after 60 seconds. A broken login (“not logged in”, a failed OAuth refresh, `invalid_grant`) is reported at once with a hint to log in again that names the provider (`diagnose` in `server.ts`). If someone has resumed the conversation and it is busy at that deadline, watchdog leaves it alone. `subagent stop` cancels that child's pending watchdog task and withdraws any queued retry input, using the stop handler's captured identities so replay leaves later work alone. A failed retry is never retried again. Persistent and non-temporary errors become a `watchdog.failure` card with the conversation, title, error, last tool step and any login hint; reporting a subagent's failure marks its parent's `failed` action for it `given-up`. @ultimate's own failure raises a notice instead. User Stops are ignored; reply-expecting Messages inputs already have a failure reply and are excluded.

A root receipt and background task are created atomically for each failed generation; retry/report submissions use stable request IDs. On open, missed failures are scanned above the stored high-water mark, never advancing past unfinished work. Fresh installation marks existing tasks as historical and reports none of them.

The `watchdog.idle` input note is only for @ultimate and only when its set of branch IDs changes. It excludes concluded, running (including owned children), recently active, user-question-waiting and lander-queued branches. A branch counts as idle after 30 minutes, since a coordinator that ended its run with nothing to wake it may have stalled; one with an open reply-expected message to another conversation gets two hours. One waiting on @ultimate's answer (an open question to it, or a report or reply since @ultimate last messaged it; echoes excluded) gets ten minutes, and once @ultimate is idle with no route or reply delivery to it pending, a background `watchdog.owed` task submits the note as a follow-up input that wakes it at once; a flagged branch stays listed until @ultimate messages it, and the note repeats only when the set changes. It lists at most ten, and clears with “No branches are idle.” It never changes the system prompt.

Watchdog keeps the last 20 reported failures (`watchdog.reported` on the root, written with each report, including @ultimate's own) and serves them through `WatchdogApi.failures(since)`, newest first; the `status` extension reports them.
